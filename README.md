# erp-query-mcp

Ask a manufacturing ERP database questions in plain English.

This is an [MCP](https://modelcontextprotocol.io) server that gives an LLM (Claude Desktop, or any MCP client) safe, **read-only** access to an ERP-style SQL database. You ask things like:

> "Which parts are below their reorder point?"
> "Who are our top 5 customers by invoiced amount this quarter?"
> "How many invoices are unpaid, and what's the total outstanding?"

…and the model uses the server's tools to discover the schema, write SQL, and answer with real numbers.

> **Origin:** generic rebuild of a tool I built during an internship at Cypress Industries, where a version of this ran against the company's production ERP and became the foundation for automated month-end reporting. This repo contains none of that code or data — the database here is 100% synthetic, generated by `scripts/seed.js`.

## How it works

The LLM does the natural-language → SQL translation. The server keeps it safe:

```
User question ──> MCP client (Claude) ──> list_tables / describe_table  (schema discovery)
                                     ──> run_query (validated SELECT)  ──> answer
```

| Tool | Purpose |
|---|---|
| `list_tables` | Tables + row counts |
| `describe_table` | Columns, types, keys for one table |
| `run_query` | A single validated `SELECT` (200-row cap) |

Guardrails: the SQLite connection is opened read-only, queries are validated (single statement, `SELECT`/`WITH` only, keyword denylist), and results are row-capped. Independent layers, so a clever prompt injection can't turn this into a write path.

## Run it

```bash
npm install
npm run seed     # creates data/erp-demo.db with synthetic manufacturing data
npm test         # validation + query tests
```

Add to Claude Desktop (`claude_desktop_config.json`):

```json
{
  "mcpServers": {
    "erp-query": {
      "command": "node",
      "args": ["/absolute/path/to/erp-query-mcp/src/index.js"]
    }
  }
}
```

Restart Claude Desktop and ask it something about the data.

## Demo schema

Synthetic mid-size manufacturer: `customers`, `vendors`, `parts` (with stock levels and reorder points), `purchase_orders`/`po_lines`, `sales_orders`/`so_lines`, `invoices`. ~400 orders spanning six months, seeded deterministically.

## What I learned

- Designing MCP tools so the *model* can navigate an unknown schema (schema-discovery tools matter more than the query tool itself).
- Treating LLM-generated SQL as untrusted input: validation, read-only connections, and row caps as independent layers.
- The difference between a demo and a production deployment: the internship version needed auth, query logging, and result-size budgets before anyone would trust it.
